## 0. 设计前提与假设

三条设计原则（所有取舍以此裁决）：

1. **打开即行动**：首页 3 秒内让用户知道"下一步做什么"，不做需要用户自己组织的空白画布。
2. **记录零摩擦**：任何页面 ≤1 次操作进入捕获状态，学习中的想法不能因为"要切页面"而丢失。
3. **数据是用户资产**：本地优先、纯文本可导出、无账号锁定；任何联网能力都是可选增强项。

以下假设未经用户确认，先按此推进；若不成立则影响范围已标注。

| 编号 | 假设 | 若假设不成立的代价 | 关联问题 |
| --- | --- | --- | --- |
| A1 | 单用户、无账号体系、本地优先 | 引入账号/同步需后端，工作量 +50%~100% | Q2 |
| A2 | 核心闭环是「计划 → 专注 → 记录 → 复盘」 | IA 与首页布局需重排，MVP 范围重划 | Q3 |
| A3 | 中文优先，同时预留 i18n 框架 | 事后补 i18n 需回改全部文案与组件 | Q5 |
| A4 | 离线可用为硬要求 | 若允许联网优先，可省掉本地迁移/冲突逻辑 | Q2 |
| A5 | 技术栈未定，设计不绑定任何框架 | 无 —— 本设计刻意不绑定框架 | Q5 |
| A6 | 目标用户是"有自主学习需求的学生 / 在职自学 / 考证备考" | 若面向 K12 或团队，权限与内容模型要重做 | Q3 |

## 2. 信息架构与页面结构

### 2.1 导航模型

一级导航固定 5 项 + 1 项设置，**顺序即使用频率**，默认落地在「今日」：

```
今日 Today ── 任务 Tasks ── 笔记 Notes ── 复习 Review* ── 统计 Stats ── 设置 Settings
                                              （* v1.0 引入，MVP 隐藏入口）
```

设计约束：

- 一级导航不超过 5 个。超过 5 个说明有功能该被合并或砍掉。
- 任何页面到「快速捕获」的距离 ≤1 次操作（快捷键或常驻输入框）。
- MVP 阶段 `Review` 不占导航位，v1.0 开启后由设置控制显隐。

### 2.2 页面 → 职责 → 区块 → 主操作

| 页面 | 核心职责（回答用户什么问题） | 核心区块 | 主操作 | 引入版本 |
| --- | --- | --- | --- | --- |
| **今日 Today** | 我今天该做什么？现在进行到哪？ | ① 日期问候 + 今日目标进度环 ② 当前聚焦任务 + 计时器 ③ 今日任务列表 ④ 快速捕获输入 ⑤ 今日笔记速览 ⑥ 近 7 天热力图 | 开始计时 / 勾选完成 / 快速记录 | MVP |
| **任务 Tasks** | 我有哪些事要做？怎么分类？ | ① 工具条（筛选 / 排序 / 搜索 / 新建）② 分组列表（按目标、标签、时间）③ 详情面板（描述 / 子任务 / 关联笔记 / 计时记录） | 新建任务 / 编辑 / 拖动排序 / 开始计时 | MVP |
| **笔记 Notes** | 我记过什么？怎么找回来？ | ① 笔记列表 + 搜索 ② Markdown 编辑 / 预览 ③ 元信息（标签 / 关联任务 / 创建时间） | 新建 / 编辑 / 打标签 / 关联任务 | MVP |
| **复习 Review** | 今天该复习哪些卡片？ | ① 到期数进度条 ② 单卡沉浸区（翻面）③ 评分（重来 / 困难 / 良好 / 简单） | 翻面 / 评分 / 暂停 | v1.0 |
| **统计 Stats** | 我投入得怎么样？趋势如何？ | ① 指标卡组（今日 / 本周时长、连续天数、完成率）② 12 周热力图 ③ 时长分布（按目标 / 标签）④ 30 天趋势折线 | 切换时间范围 / 下钻到明细 | v1.0（MVP 仅保留极简版：今日时长 + 连续天数） |
| **设置 Settings** | 我怎么调成适合自己的样子？ | ① 外观（主题 / 密度 / 字号）② 学习（每日目标 / 番茄时长 / 复习上限）③ 数据（导入 / 导出 / 快照 / 清除）④ 快捷键 ⑤ 关于与更新 | 修改并即时生效 | MVP |

### 2.3 布局骨架与断点

栅格：**12 列弹性栅格**，基础间距单位 4px，内容最大宽度随页面类型区分。

| 断点 | 宽度 | 今日 Today | 任务 / 笔记 | 统计 Stats |
| --- | --- | --- | --- | --- |
| XS（宿主窄侧栏） | < 480px | 单列，仅保留区块 ①②③，计时器收为底部常驻条 | 单列：列表 ↔ 详情为路由切换，不做并排 | 单列堆叠，热力图降为 6 周 |
| SM | 480–767px | 单列，区块 ①③④ | 列表为主，详情为抽屉 | 单列，指标卡 2×2 |
| MD | 768–1023px | 双列：左（①③④）右（②⑤⑥） | 列表 + 可折叠详情 | 指标卡 4 列，图表上下堆叠 |
| LG | 1024–1439px | 双列 + 右侧窄栏 | 左列表 / 右详情并排 | 图表 2×2 |
| XL | ≥ 1440px | 三栏：导航 + 主区 + 洞察侧栏 | 三栏：列表 + 编辑 + 元信息 | 12 周热力图 + 并排图表 |

关键降级规则（决定平台可移植性）：

- `< 480px` 时一切并排布局退化为"列表 ↔ 详情"两级路由，禁止横向滚动。
- 计时器在窄容器下从内联区块降级为**底部常驻条**（保证任何页面都能看到并操作）。
- 表格类数据在窄容器下降级为卡片列表，不做横向滚动表格。

### 2.4 平台差异：只影响适配层，不影响核心设计

| 候选平台 | 入口形态 | 可用画布 | 持久化 | 系统通知 | 全局快捷键 | 主要风险 |
| --- | --- | --- | --- | --- | --- | --- |
| DSH 插件面板 | 宿主面板 / 会话侧栏 | 窄–中（约 320–640px） | 宿主 storage 或工作区文件 | 受宿主能力限制 | 受限 | 需对齐宿主 Design Token 与文案规范；AI 联动是天然优势 |
| 浏览器新标签页扩展（MV3） | 整页新标签页 | 宽（全屏） | chrome.storage / IndexedDB | 需 `notifications` 权限 | `commands` API | 入口频率最高，天然"学习台"；但有商店审核与权限弹窗 |
| 独立 Web 应用 / PWA | 手动打开的整页 | 宽 | IndexedDB + 可选后端 | Notification API | 无 | 自由度最高，但缺"被动出现"的入口，依赖用户自觉打开 |
| VS Code 扩展 | Webview 面板 / 侧栏 | 窄–中 | globalState / 工作区文件 | 扩展通知 API | 有 | 开发者体验顺，笔记可直接落到工作区 Markdown |

**结论**：四个平台的差异集中在 4 个接缝上。核心域模型、Token、组件、IA 全部平台无关。

### 2.5 四个适配接缝（平台无关设计的落点）

| 接缝 | 职责 | 各平台差异 | 设计约束 |
| --- | --- | --- | --- |
| `Storage` | 读写实体数据与设置 | IndexedDB / chrome.storage / 宿主 KV / 文件 | 统一为异步 KV + 集合查询语义；导出格式与内部格式解耦 |
| `Notify` | 到期与复习提醒 | 扩展通知 / 系统通知 / 宿主气泡 / 无 | 无通知能力时降级为打开时聚合提示，**不得静默丢失提醒** |
| `Entry` | 入口形态与打开方式 | 新标签页 / 侧栏 / 面板 / 命令面板 | 首页必须能在 <480px 单列下成立 |
| `Shell` | 布局容器与宿主样式隔离 | 整页 / iframe / webview | 样式作用域隔离，禁止污染宿主；主题跟随宿主的开关必须显式 |

## 3. UI 设计方向

### 3.1 三个方向的共同基础（不随方向变化）

| 项目 | 规格 |
| --- | --- |
| 间距系统 | 4px 基础单位：4 / 8 / 12 / 16 / 24 / 32 / 48 / 64 |
| 栅格 | 12 列弹性栅格，间距 16px（SM 及以下）/ 24px（LG 及以上） |
| 圆角 | 4px（小控件）/ 8px（卡片）/ 12px（浮层）/ 999px（标签、进度环） |
| 动效时长 | 120ms（状态切换）/ 200ms（浮层进出）/ 300ms（页面级过渡） |
| 数字排版 | 统计数字统一 `font-variant-numeric: tabular-nums`，避免跳动 |
| 无障碍基线 | 正文对比度 ≥ 4.5:1、大字 ≥ 3:1；触控目标 ≥ 44×44px；键盘全可达；`focus-visible` 2px 描边 + 2px 偏移；尊重 `prefers-reduced-motion`；支持浏览器缩放至 200% 不破版 |
| 状态表达 | 状态不得仅靠颜色区分，必须叠加图标或文案（色盲安全） |
| 字体加载 | 默认**只用系统字体栈，零 Web 字体请求**（首屏性能优先） |

系统字体栈（中文优先，覆盖 macOS / Windows）：

```css
--font-sans: -apple-system, BlinkMacSystemFont, "PingFang SC", "Segoe UI",
             "Microsoft YaHei", "Noto Sans SC", system-ui, sans-serif;
--font-mono: ui-monospace, "SF Mono", "JetBrains Mono", "Cascadia Code", monospace;
```

### 3.2 方向 A —— 纸感书桌 Paper Desk

| 项目 | 规格 |
| --- | --- |
| 风格关键词 | 温暖、纸感、衬线、阅读灯、低饱和、慢节奏 |
| 适用场景 | 长文阅读型学习、文科/语言/备考、纸质笔记习惯用户 |
| 背景 / 表面 | `#FAF7F2` / `#FFFDF9` |
| 边框 / 分隔 | `#E8E0D5` |
| 主文本 / 次文本 | `#2B2622`（对比度 14.0:1 ✓）/ `#6B5F55`（5.8:1 ✓） |
| 强调色 | 陶土橙 `#9A3412`（6.8:1 ✓），hover `#7C2D12` |
| 语义色 | 成功 `#3F6212` / 警告 `#92400E` / 危险 `#991B1B` / 信息 `#1E40AF` |
| 字体 | 标题 Noto Serif SC / Source Serif；正文系统无衬线；数字等宽 |
| 栅格 | 12 列，正文阅读列宽限制 68ch，重留白 |
| 关键组件 | 纸质卡片（1px 暖边框 + 极浅阴影）、书签式标签、衬线标题 + 细分割线、手写感空状态插画 |
| 优势 | 情感温度高、辨识度强、长阅读舒适 |
| 风险 | 衬线中文字体需子集化自托管（否则首屏字体请求拖慢）；跨平台渲染差异较大 |
| 最适合平台 | 独立 Web 应用 / 浏览器新标签页（有整页渲染自由度） |

### 3.3 方向 B —— 焦点网格 Focus Grid（暗色）

| 项目 | 规格 |
| --- | --- |
| 风格关键词 | 深色、等宽数字、网格化、荧光强调、开发者工具感、沉浸专注 |
| 适用场景 | 编程/技术学习、夜间长时间使用、与 DSH / VS Code 宿主语境一致 |
| 背景 / 表面 / 浮层 | `#0B0E14` / `#131823` / `#1A2130` |
| 边框 / 分隔 | `#232B3A` |

### 3.5 方向对比与推荐

| 维度 | A 纸感书桌 | B 焦点网格 | C 静默留白 |
| --- | --- | --- | --- |
| 视觉辨识度 | 高 | 高 | 中 |
| 跨平台一致性 | 中（字体渲染差异） | 高 | **最高** |
| 无障碍达标难度 | 中 | 中（暗色对比陷阱） | **低** |
| 开发 + 验收成本 | 高（字体子集化） | 中 | **低** |
| 长时间使用舒适度 | 高 | 高（夜间） | 中高 |
| 数据/图表表现力 | 低 | **最高** | 中高 |
| 宿主主题冲突风险 | 高（暖色 vs 宿主冷色） | 低（宿主多为暗色） | **最低**（可随宿主切换） |
| 首屏性能 | 中（字体请求） | 高 | **高**（零字体请求） |

**推荐：方向 C 作为基准设计系统，并把方向 B 作为它的暗色主题直接交付。**

理由（按权重排序）：

1. **平台尚未确认是当前最大不确定性**。C 在四个候选平台上的表现都成立，A 在窄侧栏 + 暗色宿主下会明显失配。选 C 等于把这个不确定性从"设计返工风险"降级为"主题切换成本"。
2. **C 与 B 不是二选一，是同一套 Token 的两种取值**。深浅两套主题共享相同的语义 Token 名（`--bg` / `--surface` / `--text-primary` / `--accent` / `--border`），实现层只是换值。因此"推荐 C"并不牺牲 B 的优势，反而让 B 免费获得。
3. **无障碍是硬指标，C 的达标路径最短**。浅底深字的对比度余量最大（主文本 17.7:1），暗色方案需要逐个颜色防陷阱，验收成本更高。
4. **首屏性能**：C 只用系统字体栈，零字体请求。A 的衬线中文需要子集化自托管，在"浏览器新标签页"这种高频入口上是纯负担。
5. **A 不被废弃**：作为 v1.0 的可选主题包（同一 Token 结构换值 + 一个衬线标题 Token），在浅色基准稳定后再引入，风险与成本都可控。
